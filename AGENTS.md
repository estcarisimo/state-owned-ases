# AGENTS.md — State-Owned ASes

Instructions for AI coding agents (Claude Code, Codex, Cursor, ...) working in this
repository. `CLAUDE.md` includes this file. Humans: see `CONTRIBUTING.md`.

## What this project is

An **archived dataset**: ASes of state-owned Internet operators, from Carisimo,
Gamero-Garrido, Snoeren and Dainotti, *Identifying ASes of State-Owned Internet
Operators*, ACM IMC 2021 (doi:10.1145/3487552.3487822). Ownership was verified from June
2019 to November 2020 and is not maintained. The Python package `state_owned_ases`
validates the canonical data and generates every distribution format. It never changes
what the data says.

## Layout

```
data/canonical/*.json      SOURCE OF TRUTH: one Dataset document per dataset
data/exports/              GENERATED by `state-owned-ases export`; never edit by hand
src/state_owned_ases/
  schema.py                Pydantic ASRecord/Dataset: fields, types, constraints
  canonical.py             deterministic load/save of the canonical JSON
  exporters.py             FORMATS registry; one writer per format, no timestamps
  manifest.py              MANIFEST.json and SHA256SUMS
  build.py                 export_all(), check_exports() (stale-export detection)
  cli.py                   Typer CLI (print only here)
tools/migrate_legacy.py    provenance: legacy 2021 CSVs (git history) -> canonical
tests/golden/canonical.json  golden checksums and counts of the canonical data
docs/                      MkDocs pages; most content is included from README.md sections
```

## Commands

```bash
uv sync
uv run pre-commit install
uv run ruff check src tests tools
uv run ruff format --check src tests tools
uv run mypy src/state_owned_ases tools tests       # blocking in CI
uv run pytest --cov --cov-fail-under=90             # needs full git history (migration test)
uv run state-owned-ases check                       # exports match data/canonical/
uv run state-owned-ases export                      # regenerate data/exports/
uv run --group docs mkdocs build --strict
```

## Conventions

- Python 3.10+ syntax (`X | None`, `list[str]`); ruff target `py310`; line length 100.
- `pathlib.Path`; `logging` with a module-level logger; `print`/`typer.echo` only in
  `cli.py`. NumPy-style docstrings on public API; type hints everywhere.
- American English everywhere: identifiers, docstrings, comments, messages, docs,
  CHANGELOG, commit messages, PR text (`normalize`, `behavior`, `color`). Quoted titles,
  names, URLs and the data's own text stay as they are.
- Each test carries exactly one marker, `math` (independent recomputation, e.g. reading
  an export with pandas/DuckDB) or `behavior` (pins current behavior); usually set with a
  module-level `pytestmark`.
- `CHANGELOG.md`: a bullet under `[Unreleased]` for every user-visible change. Keep
  **data content** changes (`Fixed (data content)`) separate from representation
  changes. Version lives in `pyproject.toml` and `CITATION.cff`.
- Do not edit `uv.lock` by hand. CI uses `uv sync --locked`.

## Things that are easy to get wrong

- **Never edit `data/exports/`.** Edit `data/canonical/`, then run
  `uv run state-owned-ases export`. CI runs `check` and fails on stale exports.
- **Changing the data is a scientific change.** It needs a reason, a CHANGELOG entry
  under `Fixed (data content)`, an updated `tests/golden/canonical.json`, and an
  old-vs-new comparison in the PR description. Do not "refresh" ownership from current
  sources: that would be a new dataset, not this archive.
- If a canonical change comes from the legacy files, add it to `CORRECTIONS` in
  `tools/migrate_legacy.py` and re-run the script. `tests/test_migration.py` requires the
  script to reproduce `data/canonical/` exactly.
- `NA` is Namibia's country code. Any pandas `read_csv` needs `keep_default_na=False,
  na_values=[""]`.
- Evidence is per AS: one `org_id` can have different quotes/URLs on different ASes.
- AS6713 is in both datasets on purpose (majority UAE via Etisalat, minority Morocco).
- Text exports must stay byte-reproducible: no timestamps, fixed ordering, gzip
  `mtime=0`. Parquet/SQLite are compared by content, not bytes.
- Python blocks in `README.md` and `docs/*.md` are executed by `tests/test_docs.py`
  from the repository root. Keep them runnable and fast.

## Pull request workflow (required)

`main` is protected by the `protect-main` ruleset: no direct pushes, PR required, the
`lint`, `test (...)`, `data` and `docs` checks required, review threads resolved.

**Every PR gets an independent review from a fresh session, and no PR is merged until
CI is green and that review returns `VERDICT: APPROVE` on the final commit.** "Fresh"
means a reviewer with no context from the session that wrote the change: a new AI agent
session started for the review alone (a Claude Sonnet subagent today), or a human. It
follows `.github/REVIEW.md` and is given the PR number and nothing else.

1. Branch from `main` (`feat/…`, `fix/…`, `docs/…`, `chore/…`, `data/…`), commit,
   push, `gh pr create`. Fill in the PR template honestly.
2. Wait for CI (`gh pr checks <n> --watch`). If anything is red, read the log, fix it,
   and push.
3. Start a fresh reviewer with `.github/REVIEW.md` and the PR number. Post its full
   verdict as a PR comment (`gh pr comment <n> --body-file <verdict.md>`), prefixed with
   the round number and the commit reviewed.
4. For each finding, fix it, or rebut it with evidence in a PR comment.
5. After any push, start **another** fresh reviewer (never reuse a session). Repeat
   until CI is green and the latest commit has `VERDICT: APPROVE`.
6. Merge with `gh pr merge <n> --squash`. Never merge red, and never merge without an
   APPROVE on the final commit. Do not use the admin bypass.

Never push directly to `main`, never force-push a shared branch, never weaken a CI check.
Only one PR touching `CHANGELOG.md` may be open at a time.

## Session continuity

The maintainer keeps the roadmap and a session log in a private Notion page ("State-owned
dataset"). Read the latest entry at the start of a session. At the end, record what was
done, what was verified, what is pending, and the next action, with branch/commit/PR.
